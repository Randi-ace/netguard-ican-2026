# 净网护航数据库变更规则

## 1. 目的

数据库结构是 backend、extension 和 UI 协作的公共契约。团队以仓库内审核通过的 SQL 和结构文档为准，任何成员的本地数据库都不能替代版本化脚本。

## 2. 数据库负责人制度

backend 负责人是数据库结构负责人，负责：

- 表结构设计与评审；
- 初始化脚本维护；
- migration 编写、测试与执行；
- 字段、索引、外键和约束调整；
- 数据库结构文档与 API 映射同步；
- 生产数据库变更和回滚判断。

extension 和 UI 成员：

- 通过后端 API 读写业务数据；
- 不直接连接、修改或依赖数据库内部结构；
- 不自行创建表、字段、索引或执行迁移；
- 需要数据库调整时必须先提交 Issue。

## 3. 数据库变更 Issue

Issue 至少应说明：

```text
标题：database: <变更目的>

需求：
需要支持什么功能或场景。

建议变更：
希望新增或调整的表、字段、索引；不确定时可留空。

原因：
现有 API 或结构为什么不能满足需求。

影响范围：
涉及 backend、extension、UI、历史数据或部署的哪些部分。

验收方式：
如何确认变更生效且没有破坏兼容性。
```

未经 backend 负责人确认，不得先在共享库或生产库中实施。

## 4. 标准变更流程

```text
提出需求并创建 Issue
↓
backend 负责人评估结构与兼容性
↓
修改 init.sql 和新增 migration 脚本
↓
同步数据库结构与 API 文档
↓
本地空库初始化测试
↓
本地旧库预检查、迁移与回滚测试
↓
提交 Git 和 Pull Request
↓
backend 负责人审核
↓
合并 develop
↓
按发布计划执行数据库变更
```

已发布或已被成员使用的 migration 文件不得删除、重命名或直接改写语义。新的结构变化应新增 migration 文件。

## 5. 禁止事项

- 禁止直接修改数据库表结构；
- 禁止直接使用 `ALTER TABLE` 修改生产数据库；
- 禁止 extension 或 UI 绕过 API 直接访问数据库；
- 禁止提交数据库备份文件；
- 禁止提交真实用户、检测历史、日志或成员测试数据；
- 禁止为了匹配单个成员的本地数据库而机械增加无代码依赖的表；
- 禁止绕过预检查执行迁移。

## 6. Pull Request 检查项

- [ ] 已关联数据库变更 Issue；
- [ ] 变更由 backend 负责人确认；
- [ ] `database/init.sql` 可在 MySQL 5.7.26 空库执行；
- [ ] 新 migration 不依赖 MySQL 8.0 专属语法；
- [ ] 字符集为 `utf8mb4`，排序规则为 `utf8mb4_unicode_ci`；
- [ ] 未包含真实数据、测试数据或备份文件；
- [ ] 已验证备份、预检查、迁移、结果验证流程；
- [ ] 已同步数据库结构文档；
- [ ] API 字段受影响时已同步 API 契约；
- [ ] 已说明回滚或恢复方案。

## 7. 紧急变更

生产故障也不得跳过留痕。确需紧急处理时，由 backend 负责人执行最小变更，先备份并记录命令、时间和影响范围，随后立即补齐 Issue、migration、文档和 Pull Request。
